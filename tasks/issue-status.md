# تقرير مراجعة قضايا PandaSpigot

**آخر تحديث: 2026-10-19.** النطاق هو القضايا المفتوحة الـ33 التي جُمعت من GitHub مع تعليقاتها في التدقيق السابق، بالإضافة إلى فيديو البناء السريع. لم تُغلق أي قضية على GitHub ولم تُرسل تعليقات. هذا التقرير يصف النسخة المحلية؛ وجود تنفيذ أو اختبار وحدات لا يعني إثبات اختفاء كل أعراض البلاغ في كل بيئة.

## تحديث SlimeWorldManager — النسخة r2

أُصلح خطأ "sealing violation: package org.yaml.snakeyaml.util is sealed" الذي ظهر بعد استبدال السيرفر. كان سببه وضع Sealed في القسم العام من Manifest. اختُبرت نسخة SWM 2.2.1 والـclassmodifier المحلية على Java 21: تكرر الخطأ قبل الإصلاح واختفى بعده. النسخة المعتمدة الآن في "build/releases/2026-10-19-r2/". راجع [تقرير الإصلاح](sealing-fix-2026-10-19.md).

## النتيجة الحالية

- **تحديث ViaAck 1.0.1 — الحزمة r3:** أُعيد إنتاج رسالة `ViaVersion ACK provider unavailable` بالنسخة القديمة عند تأخير تهيئة ViaVersion، ثم نجحت النسخة الجديدة في الحالة نفسها. تنتظر اكتمال post-enable حتى 60 ثانية وتقبل مزوّدي ACK الرسميين. نجح تشغيلها مع ViaVersion وViaBackwards 5.5.1 أيضًا؛ هذا اختبار بدء تشغيل، واختبار عميل 1.21.11 بقي على ViaVersion 5.12.1. راجع [التقرير التفصيلي](viaack-startup-fix-2026-10-19.md).
- اكتمل بناء السيرفر والـAPI وإضافة ViaAck. انتهى عائق API المذكور في النسخة السابقة من هذا التقرير.
- آخر نتائج المكونات: السيرفر **5,447 اختبارًا ناجحًا**؛ API **990 ناجحًا و3 متجاوزة**؛ ViaAck **13 ناجحة**. المجموع **6,450 ناجحًا، صفر فشل، 3 متجاوزة**، مع نجاح smoke compile لحزمة API المستقلة. تحديث 1.0.1 أعاد بناء وفحص الإضافة واختبارات التشغيل فقط؛ لم يتغير مصدر السيرفر أو API بعد فحصهما السابق.
- توجد تغييرات محددة لـ**26 قضية** ضمن حدود التحقق الموضحة أدناه. روجعت قضيتان دون تغيير تخميني (#96 و#242). خمس قضايا ما زالت جزئية أو غير مكتملة (#69، #104، #164، #344، #413). لا أعدّ القضايا الـ33 كلها محلولة.
- صُدّرت التغييرات إلى **server 0139–0149** و**API 0034–0037**. أُعيد تطبيق هذه الـ15 patch على نسخ منفصلة من آخر مصدر سابق للتدقيق، وتطابقت أشجار Git الناتجة حرفيًا مع المصادر الحالية. لم تُختبر إعادة بناء upstream كاملًا من الصفر في هذا التحقق.
- لم يُنشأ commit في المستودع الجذر، وبقي تعديل المستخدم السابق في Gradle wrapper محفوظًا. commits داخل أشجار المصدر المولّدة استُخدمت لتصدير patches فقط.

## مشكلة الفيديو: البناء السريع من 1.21.11

أكّد المستخدم أن ViaVersion داخل `plugins` على نفس PandaSpigot، ومعه ViaBackwards. في الفيديو تظهر بلوكات متوقعة من العميل ثم تختفي/تتراجع عند بناء سلسلة سريعة. هذا يتسق مع خلل ترتيب تصحيح البلوك وتأكيده، لكنه وحده لا يثبت أن هذا هو السبب الوحيد في بيئة التسجيل.

الإصلاح المحلي يتكون من **ملفين مطلوبين معًا**:

1. السيرفر المعدل: يضيف `NetworkManager.executeAfterQueuedPackets`؛ الحاجز ينتظر حزم الإرسال السابقة، حتى حزم الـchunk غير الجاهزة، ثم يرسلها قبل التأكيد.
2. الإضافة الاختيارية `PandaSpigotViaAck`: تحفظ sequence خاصًا بكل عملية، تنتظر رجوع استدعاء الترجمة إلى event loop، ثم معالجة الحزمة في طابور السيرفر الرئيسي، ثم حاجز الإرسال، وأخيرًا ACK. لا تعتمد على sequence متغيّر مشترك يمكن أن يشير إلى عملية أحدث لم تُعالج بعد.

أُصلح أيضًا ترتيب بدء الإضافة في 1.0.1: تنتظر اكتمال post-enable الخاص بـViaVersion وتعيد فحص الجاهزية حتى 60 ثانية، وتقبل مزوّد Bukkit والمزوّد الأساسي الرسميين. محاولة التأخير الوحيدة في 1.0.0 لم تكن كافية في كل حالات التهيئة. تتوقف عند عدم وجود امتداد السيرفر المطلوب أو وجود ACK provider من طرف ثالث؛ وعند تعطيلها تعيد provider الأصلي. تسجّل نسخة ViaVersion الفعلية، وهي مستقلة عن اسم ملف ViaBackwards الذي أكده المستخدم.

### دليل التشغيل

شُغّل سيرفر محلي مع **ViaVersion 5.12.1** واتصال TCP فعلي لعميل بروتوكول **1.21.11**:

| السيناريو | النتيجة |
|---|---|
| 40 عملية بناء متسلسلة سريعة في Creative | نجحت؛ تحديث البلوك سبق ACK لكل عملية. |
| 40 عملية في Survival | نجحت بالشرط نفسه. |
| عملية مرفوضة في Adventure | وصل تصحيح الهواء قبل ACK. |
| اتصال 1.8.9 أصلي | نجح وضع بلوك دون الاعتماد على ACK الحديث. |
| خروج ورجوع لاعب إلى نطاق التتبع 3 مرات | وصلت خانات العتاد الخمس (السلاح وأربع قطع درع) بعد spawn في كل مرة. |
| وحدات الإضافة وحاجز الشبكة | ترتيب متداخل، حزم مؤجلة، إلغاء، قطع اتصال، وتعطيل الإضافة: ناجحة. |

**81 ACK من 81 وصلت بعد تحديث البلوك الصحيح.** التفاصيل في `build/issue-audit/live-server/result.json`، وتسلسل الحزم في `packets.json`، والعتاد في `tracking.json`. إعادة التشغيل موضحة في [اختبار البروتوكول](../compatibility/via-ack/integration/README.md).

هذا اختبار حقيقي لمسار الشبكة والترجمة، وليس تجربة رسومية للفيديو على سيرفر المستخدم بكل إضافاته. لم تُختبر إضافات منع الغش/الميني جيم الخاصة به أو latency/low TPS الفعليان. لم يحتج الاختبار ViaBackwards لأن الاتجاه هو عميل أحدث إلى backend أقدم. يجب تجربة الحزمة على البيئة التي سُجّل فيها الفيديو قبل إعلان اختفاء العرض هناك نهائيًا.

### التركيب

الحزمة المصححة الجاهزة في `build/releases/2026-10-19-r3/`. تحتوي السيرفر `PandaSpigot-1.8.8-2026-10-19-r2.jar` نفسه، وإضافة `PandaSpigotViaAck-1.0.1.jar`. إذا كان r2 مثبتًا: أوقف السيرفر، أزل نسخة ViaAck القديمة من `plugins` وضع الجديدة بجانب ViaVersion، ثم أعد التشغيل على Java 17 أو أحدث. رسالة النجاح هي `Ordered block ACKs enabled with ViaVersion ...`. السيرفر القديم قبل إصلاح حاجز الشبكة مع الإضافة لا يكفي، والسيرفر الجديد وحده لا يغيّر provider الخاص بـViaVersion.

### حدود إعدادات الأداء #397

الإعدادات موثقة في [configuration.md](configuration.md). Defaults تحفظ اللعب الاعتيادي. تعطيل villagers يرفض الجديدة ويجمّد الموجودة ويحفظ بياناتها؛ ليس حذفًا جماعيًا لتوفير RAM. تعطيل tracking يوقف التحديثات الدورية مع إبقاء spawn/remove. redstone toggle يوقف scheduled ticks للمكونات المعنية، ولا يدّعي منع كل تفاعل مباشر مع ريدستون. XorShift يغير النتائج العشوائية ويتطلب restart/world reload.

القيمة `entity-activation-range: 0` في Spigot **تعني استمرار التحديث دائمًا**؛ لذلك لم تُطبّق توصية الاقتراح بصورة تعكس هدفها. أُضيف `disableNonPlayerEntityTicking` لتحقيق التجميد صراحة. منطق dirty chunks الموجود أصلًا يتجنب حفظ الأرض غير المعدّلة، لكنه يحفظ chunks التي تحتوي كيانات دوريًا؛ إلغاء ذلك قد يفقد تحديثات الكيانات.
